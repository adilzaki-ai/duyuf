# Duyuf — notes for Claude

Hajj and Umrah operations platform for Saudi service companies. Owner: Adil.
Sister project to Sky Logics (`../react skylogics`); same shape, separate code,
database and ports. Never touch Sky Logics from here.

## Shape
- Backend: `backend/api/duyuf` (FastAPI). Every request runs in
  `tenant_session()` as role `duyuf_app` with `duyuf.tenant_id` set; RLS does the
  isolation. `owner_session()` is for scripts and credential checks (keys, sign in,
  sessions, passwords) inside `core/auth.py` only, never in a router.
- New table → its own migration in `backend/db/migrations/NNNN_*.sql`, with
  explicit GRANTs to `duyuf_app` and the RLS loop (see 0003). No default privileges.
- Routes ask for a scope (`require("pilgrim:write")`), never a role. Roles → scopes
  in `core/auth.py`.
- Journey moves live in `backend/api/duyuf/pilgrims/status.py` and are mirrored in
  `frontend/src/domain/journey.ts`; a frontend test reads the Python file, so
  change both. Same for the flight brief rules: `arrivals/brief.py` ↔
  `frontend/src/domain/brief.ts`, and the gap rule: `arrivals/plan.py` ↔
  `domain/plan.ts`, and incident moves: `incidents/flow.py` ↔ `domain/incidents.ts`,
  and Rafeeq's languages and calls: `rafeeq/help.py` ↔ `frontend/src/rafeeq/help.ts`,
  and the health rules: `health/rules.py` ↔ `frontend/src/rafeeq/vitals.ts`.
- Frontend: screens use `DataSource` (`api/dataSource.ts`), never `fetch`.
  `PlatformSource` = backend, `MockSource` = `sample/demo.json`.
- One sample: `sample/demo.json`, generated by `backend/scripts/make_demo_sample.py`,
  loaded into the `duyuf-demo` operator by `seed_demo.py` and served by MockSource.
  Never write sample data into a non-demo operator; `is_demo` is fixed at creation.

- Rafeeq (`/r#rfq_…`): the pilgrim's own phone page, a separate app in the same
  build (`src/rafeeq`, split off in `main.tsx`). A card's secret is hashed and
  looked up as the owner in `core/auth.py` (`card_holder`); it opens only
  `/v1/rafeeq/*`. A call for help never falls back to the sample: when it does
  not reach the platform the page says "NOT sent" and shows the numbers.
  Its six languages live in `rafeeq/words.ts` (`say()`), not `ar.ts`; a test
  fails when a line lacks one. Safety words only, no religious content.
- Health (`health/`): heart rate, temperature, water and place, only with the
  pilgrim's consent (`pilgrim_consent`). Thresholds in `health/rules.py` are
  PROPOSED (no doctor has agreed them) and mirrored in `frontend/src/rafeeq/vitals.ts`.
  Danger counts down 30 s on the page; `core/jobs.py` (started in `main.py`'s
  lifespan) turns a countdown that ran out into an urgent medical incident. Jobs
  are the one other place that reads across operators as the owner. Readings
  are health:read only (medic, administrator); other staff get the place, never
  the numbers. Readings kept 7 days, places 48 hours (PROPOSED).
- Ask Rafeeq (`rafeeq/ask.py`): one Claude call per question, structured
  {answer, action}; the pilgrim's own page as words (first name, group,
  meeting point, states not numbers; never passport, birth date, surname,
  phones). Model `DUYUF_RAFEEQ_MODEL` (default Opus 5.5; Haiku 5.5 is the
  cheap option, the operator's call). The demo asks Claude through the
  viewer's `sample` capability with the SAME rules, read from ask.py by
  `frontend/src/rafeeq/askRules.ts`, so change the rules in ask.py only.
- Rafeeq's look: the mark is `rafeeq/Logo.tsx`; Reem Kufi is for the name
  only. The cover (`Cover.tsx`) shows on a card's first opening only, never
  in front of SOS on later visits.
- AI analyst (`analyst/`): aggregates only, agreed with Adil. Its tools never
  return names, passports, birth dates, phones or incident descriptions;
  `test_no_tool_lets_a_person_out` enforces it. Key in `backend/.env.local`.

## Text
- English is the key: `t("Pilgrims")`, Arabic in `src/i18n/ar.ts`. A test fails
  when a `t("…")` string has no Arabic. Use logical CSS (`inline-start`), not left/right.
- Inside Arabic text, keep Latin runs whole: `ltr()` for time ranges and codes,
  `route()` for "from → to", `sep()` for list commas, `<bdi>` around flight or
  group links, `dir="auto"` on anything staff typed. Check with `?lang=ar`.
- Plain short American English on screen; subtitles of 8 words or fewer.
- Dates: Gregorian with the Umm al-Qura Hijri date beside it; "today" is Asia/Riyadh.

## Checks
- `cd backend && ./run-tests.sh` (duyuf_test, rebuilt each run; never duyuf_dev).
- `cd frontend && npx tsc -b && npx vitest run` — `tsc -b`, not `tsc --noEmit`.
- Look at the real page with nothing clicked before saying a screen works.
